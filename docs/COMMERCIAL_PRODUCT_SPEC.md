# RelayGuard 販売資料（2026-09-17 改訂）

> 非正本資料（製品仕様の正本は `Relay_Guard/SPEC_INDEX.md`）。旧版にあった「L0即時自動送信」「数学的に証明可能」「100%予測可能」「GDPR準拠」「業務30〜50%削減」「リスクをゼロ化」等の表現は、実装・検証の根拠がない、または現MVPの範囲（送信しない）と矛盾するため削除した。販売時もこれらを主張しないこと。

## 1. 一言で

**「相談相手のいない一人事業者が英語で返信するとき、自分が承認していない約束を1語も混ぜない」ためのローカル確認ツール。**
返信文を作るだけでなく、*承認内容と返信文を機械的に照合して、ずれたら止める* のが売りです。

### 画面で言い切る一文（2026-09-19 人間決定）

> **「これは、私が考えて書いたものです。そして、それ以外はAIによる意図が入っている言葉です。」**

返信案は一様な英文の塊ではなく、1行ずつ出どころが分かれています。RelayGuardはそれを画面に出します。

| 行の種類 | 誰のものか |
|---|---|
| 定型 | 完全に機械。値も約束も含まず、案件によって変わらない |
| あなたの文 | 完全にあなた。あなたが書いた英文がそのまま入る |
| 承認済み | 中間。中身はあなたが承認した内容で、文面は機械が組み立てた |
| 由来なし | どの承認にも対応しない行。あると検査で停止する |

他社の生成ツールがこれを示せないのは、全文をLLMが書いており **区別が存在しない**ためである。RelayGuardはこの区別を閉世界検査のために元から計算している（表示するだけで、判定は一切変わらない）。

## 2. 誰の、どんな痛みか（2026-09-17 人間決定）

**顧客像: 相談できる人がいない、英語が苦手な個人事業主・一人SaaS運営者。**
上司・法務・英語が得意な同僚・外注の専門家がいない、ヒアリングや専門家レビューを受ける手段もない人。作り手自身がこの顧客像である。

| 場面 | 痛み | RelayGuardでの解決 |
|---|---|---|
| 海外ユーザーからの問い合わせ・返金要求 | 翻訳AIの英文に「返金します」「保証します」「明日対応」が紛れても、確認してくれる人がいない | 自分がDecision Sheetで承認していない金額・日付・保証・返金・約束が入ると停止 |
| 怒り・解約・法的な言及を含むメール | 一人で抱え、焦って約束しすぎる | 法的主張・AIへの指示文を含む案件はL3でAI処理停止し、人間の対応を促す |
| 後から「何を約束したか」を確かめたい | 記録を整備する余力がない | 承認者・版・ハッシュの監査チェーン（本文は保存しない＝保管責任を増やさない） |

設計上の帰結: **「相談相手の代わりに止める」ことが価値**。そのため、導入支援・専門家伴走を前提にしない、セルフサーブで完結する製品にする。

## 3. 差別化（事実として言えること）

1. **照合して止める**: 翻訳・作文ツールは「それらしい英文」を出すだけ。RelayGuardは返信を、承認内容を見ない独立した抽出器で読み直し、金額（Decimal比較）・通貨（ISOコード、`$`を推測しない）・日付・timezone・数量・条件・約束を型付きで照合します。
2. **閉じた世界の検査**: 承認済みの行以外の文が1行でも足されると停止。「意味を理解したつもり」にならない設計です。
3. **判定はコード、LLMは任意の入口だけ**: L0〜L3判定・検査・承認はすべて決定論的なPython。LLM（Claude）は任意で解釈の下書きに使うのみで、出力は原文の完全一致引用などの検証に通らなければ採用しません。
4. **送らない**: 最終承認→コピーで止まる。誤送信の経路をそもそも持たない。
5. **データを残さない**: 案件はメモリ上のみ（既定24時間）、ログはID・ハッシュ・判定コードのみ。
6. **どこまでが自分か見える**: 返信案の各行に「定型／あなたの文／承認済み／由来なし」を表示。自分が書いた文と、機械の意図が入った文の境界が読む前に分かります。

### 検証で言える数字（合成データ・開発用検証である旨を必ず併記）

- 合成評価セット122件（100件評価セット＋SG-001 fixtures）: L3は72件すべて返信生成を拒否。返信を作った53件のうち41件が検査通過、12件は相対日付や型付き根拠のない日付等で停止。
- 検査通過した返信への改ざん攻撃（金額・通貨・記号化・条件削除・保証/返金/値引き/相対期限/第三者メール/指示文/無関係文の追加）: デモでは適用310件中310件を停止。テストでは23種類の攻撃を全通過案件に適用。
- 自動テスト2,400件超・mypy strict・ruff すべて通過。
- **未実施**: 独立QA、実メールでの評価、利用者テスト。営業資料で「実績」として示さないこと。

## 5. 売り方（セルフサーブ前提）

1. **まず作り手自身が毎日使う**（ドッグフーディング）。自分の実メールで、止まりすぎ・取りこぼし・英文の不自然さを記録する。これが最初の実データ評価になる。
2. 同じ境遇の人が見る場所で、「一人で英語対応していて約束しすぎた/しそうになった」体験と、それが止まる様子（合成サンプル）を公開する（note・Qiita・Zenn・個人開発者コミュニティ）。
3. 配布はBOOTH・自前サイト等の直販。問い合わせ対応を最小にするため、ガイドとFAQで自己解決できるようにする。

## 6. 製品化までに残る作業

| 優先 | 作業 | 理由 |
|---|---|---|
| 必須 | 作り手自身の実メールでの試用と、止まりすぎ/取りこぼしの記録 | 評価が合成データのみ。専門家やパイロット企業を使えない顧客像なので、自分が最初の検証者 |
| 一部済 | Python不要の配布（zip＋`RelayGuard.exe`、2026-09-17）。残り: コード署名、更新手段 | 非エンジニアが使える形。署名なしはSmartScreen警告が出る |
| 必須 | 日本語だけで分かる停止理由・次の行動の表示 | 相談相手がいない利用者が自力で判断できる必要がある |
| 必須 | 利用規約・免責（送信内容の責任は利用者、安全を保証しない）、プライバシーポリシー、Anthropic APIへの送信の説明 | 外部API送信機能があるため。専門家レビューを受けられない前提で、保守的な文言にする |
| 必須 | 作り手以外による攻撃テスト（別セッションのAIによる独立レッドチームを含む） | 同一開発者の自己検証しかない。人間の専門家を使えない前提での代替手段 |
| 推奨 | 承認済み定型文の登録（自分の言い回しを一度承認して再利用） | 定型構造の英文が最大の弱点 |
| 見送り | 複数オペレーター・チーム承認・本文の永続保存 | 顧客像（一人運営）に不要。本文保存は保管責任を増やすため採らない（人間決定） |

## 7. 言ってはいけないこと

- 「安全を保証」「100%防ぐ」「事故ゼロ」「法令準拠（GDPR/個人情報保護法）認証」
- 「自動で返信・送信する」（MVPは送信機能を持たない）
- 合成データの数字を実運用の実績として示すこと
