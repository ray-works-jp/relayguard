# 実メール試用記録（英文メール5通）

作成: 2026-09-19 / 記録者: （あなた）

目的は「RelayGuardが自分の役に立つか」を5通で判定すること。良し悪しを感覚で終わらせないために、**基準を先に決めてから**始める。

---

## 0. 始める前に（1回だけ）

- [ ] Anthropic の APIキーを作る（Console → API Keys）。キーは環境変数 `ANTHROPIC_API_KEY` に設定する。**このファイルにも、チャットにも貼らない。**
- [ ] 起動する（配布版・Python不要）:
  ```
  RelayGuard.exe --enable-llm-interpreter
  ```
  ソースから動かす場合:
  ```
  .venv/Scripts/python.exe scripts/run_reviewer.py --operator your_name --enable-llm-interpreter
  ```
- [ ] 顧客の個人情報が濃いメールは対象にしない（または伏せてから使う）。本文はAnthropic APIへ送信される。

### 判定基準（先に決める。あとで変えない）

| 結果 | 条件 |
|---|---|
| **成功** | 5通のうち1回でも、自分が書いていたはずの未承認の値・約束（金額・期限・保証・返金など）が止まった |
| **成功** | または、1通あたりの作業時間が、自分でゼロから英文を書くより短く感じた |
| **失敗** | 5通とも「止まるだけで役に立たない」「結局は自分で書き直した」 |
| **保留** | 5通とも返信不要のメールだった（対象のメールが来ていないだけ。判定しない） |

失敗も立派な結果。**「自分にも要らなかった」と分かれば、そこで手を引ける。**

## まとめ（5通終わってから書く）

- 通した数:　　通（うち 返信不要 　通）
- 止まった回数:　　回
- そのうち、**自分が書いてしまっていた**もの:　　回　←　ここが0なら、この製品はあなたには不要かもしれない
- 止まりすぎて邪魔だった回数:　　回
- APIにかかった金額（Console の Usage で確認）:　　円くらい
- 判定:　成功 / 失敗 / 保留
- 次にどうする:

### 判定が「成功」だったとき

- 止まった実例を1つ、そのまま文章にする（相手が特定できない形で）。売る材料としては、合成データの数字よりこれが強い。
- 何度も書く言い回しがあれば、定型文として登録できるようにする（未実装。必要になったらClaude Codeに依頼）。

### 判定が「失敗」だったとき

- 理由を1行でいい。「止まりすぎ」「英文が硬い」「取り込みが面倒」など。
- そのまま売る方向は見直す。作業を止めるのも選択肢。

### 判定が「保留」だったとき

- 対象の英文メールが来ていないだけ。期限を決めず、来たときに再開する。
